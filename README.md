# Local Video Agent

A fully local, modular AI animated video production studio.

The long-term goal is to turn a single request such as:

> “Create a five-minute motivational animated story in English with cinematic illustrations, consistent characters, my preferred narrator voice, emotional music, sound effects and subtitles.”

into a validated, YouTube-ready MP4 using local models and services.

## Purpose

Local Video Agent will eventually provide:

1. story and narration generation
2. scene-by-scene storyboard creation
3. consistent illustrated scene generation
4. scene animation through ComfyUI workflows
5. local narration with Chatterbox Multilingual TTS
6. background music and sound effects
7. audio/video synchronization
8. subtitle generation
9. final MP4 rendering with FFmpeg
10. output validation

Production is scene-based and will use a `scenes.json` manifest. Finished videos must never be overwritten without explicit permission.

## ComfyUI integration

ComfyUI is contacted through its HTTP API.

Endpoints used:

- `GET /system_stats`
- `POST /upload/image`
- `POST /prompt`
- `GET /history/{prompt_id}`

The tested workflow is `ltx_image_to_video_api.json`.

Key settings:

| Setting | Value |
|---|---|
| Model | `ltxv-2b-0.9.6-distilled-04-25.safetensors` |
| Resolution | `768x512` |
| Frames | `97` |
| FPS | `24` |
| Output | `video/h264-mp4` |

Important: this workflow has already been tested successfully. Do not replace it or break its MCP integration.

`server.py` reads `COMFYUI_URL` from the environment for the status tool. `comfyui_client.py` currently uses the default local URL directly. This is harmless in the current single-machine setup and is intentionally unchanged.

## TTS setup — installed, smoke tests passed

Chatterbox Multilingual TTS is installed in `.venv-tts`. Short English and Hindi CUDA inference both passed using the cached model. The next milestone is the TTS core service.

### Official sources

- Repository: https://github.com/resemble-ai/chatterbox
- PyPI: https://pypi.org/project/chatterbox-tts/
- Windows/RTX issue: https://github.com/resemble-ai/chatterbox/issues/64

### Compatibility notes

Chatterbox supports English (`en`) and Hindi (`hi`). There is no official Hinglish language code, so Hinglish quality must be evaluated through practical testing.

Voice conditioning is supported through `audio_prompt_path`. Only recordings we own or are explicitly authorized to use may be used as references.

Expressiveness is controlled through parameters such as:

- `exaggeration`
- `cfg_weight`
- `temperature`
- `repetition_penalty`
- `min_p`
- `top_p`

There is no direct speaking-speed parameter in the official API. Speed control will require indirect parameter tuning or post-processing.

### Dependency warning

A plain install is **not safe** for this project:

```powershell
pip install chatterbox-tts
```

Chatterbox `0.1.7` pins:

```text
torch==2.6.0
torchaudio==2.6.0
```

for Python versions below 3.14. Our Python is 3.11, so a normal install would downgrade the working CUDA 13.0 / Blackwell stack.

The controlled installation is complete: `chatterbox-tts==0.1.7` was installed with `--no-deps`, followed by explicit compatible dependencies. `torch==2.10.0+cu130`, `torchaudio==2.10.0+cu130`, and `numpy==1.26.4` were preserved or restored. Gradio was not installed. See `docs/adr/0002-chatterbox-dependency-strategy.md` and `docs/adr/0003-windows-tts-dependency-pins.md`.

`pip check` reports expected Chatterbox metadata conflicts only: missing Gradio and a preference for Torch/TorchAudio `2.6.0`. These conflicts are intentional. Do not resolve them by downgrading Torch, TorchAudio, or CUDA, and do not install Gradio just to satisfy metadata.

WAV output uses `soundfile.write(...)` rather than `torchaudio.save(...)`, because the current environment does not include TorchCodec. Package imports, language codes, CUDA kernel execution, and short English/Hindi model inference have all passed. The smoke-test WAVs were 24 kHz, non-silent, and 3.52 s / 4.52 s respectively.

Before any GPU TTS stage, check ComfyUI VRAM: an empty render queue does not mean VRAM is free. If `GET /system_stats` shows low free VRAM, call `POST /free` with `{"unload_models":true,"free_memory":true}` and verify availability before starting TTS. ComfyUI reloads its models on the next render.

## Repository hygiene

Do not commit or upload:

- model weights or checkpoints
- personal voice recordings
- generated videos, audio, or large generated images
- credentials, tokens, API keys, or `.env` files
- ComfyUI runtime outputs

`.gitignore` is configured for these exclusions while preserving source code, workflow JSON, documentation, and dependency manifests.

The project is not yet a Git repository and has no remote. No remote will be added and nothing will be pushed until the GitHub repository URL and visibility are confirmed.
