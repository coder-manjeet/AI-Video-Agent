# Local Video Agent

A fully local, modular AI animated video production studio.

The long-term goal is to turn a single request such as:

> “Create a five-minute motivational animated story in English with cinematic illustrations, consistent characters, my preferred narrator voice, emotional music, sound effects and subtitles.”

into a validated, YouTube-ready MP4 using local models and services.

## Purpose

Local Video Agent will eventually provide:

1. story and narration generation
2. scene-by-scene storyboard creation
3. consistent illustrated scene generation
4. scene animation through ComfyUI workflows
5. local narration with Chatterbox Multilingual TTS
6. background music and sound effects
7. audio/video synchronization
8. subtitle generation
9. final MP4 rendering with FFmpeg
10. output validation

Production is scene-based and will use a `scenes.json` manifest. Finished videos must never be overwritten without explicit permission.

### Existing MCP tools

Defined in `server.py` (`local-video-agent`):

- `comfyui_status()` — checks ComfyUI system stats
- `create_video(image_path, prompt)` — uploads an image and submits the LTX workflow
- `check_video_status(prompt_id)` — retrieves job status and output details

Defined in `tts_server.py` (`local-tts-agent`):

- `generate_speech(text, output_path, language="en", voice="chatterbox-default-narrator", reference_wav=None, expressiveness=None, overwrite=False)` — generates a 24 kHz WAV; existing files are refused unless `overwrite=True`
- `get_audio_metadata(wav_path)` — returns path, duration, sample rate, sample count, peak and RMS without loading a model

Defined in `media_server.py` (`local-media-agent`):

- `probe_media(path, timeout_s=None)` — ffprobe stream metadata with structured errors for missing/invalid files
- `merge_narration(video_path, narration_path, output_path, volume=1.0, duration_policy="trim_audio", overwrite=False, timeout_s=None)` — renders a validated MP4 and reports every duration adjustment
- `validate_media(path, expected_duration_s=None, duration_tolerance_s=0.5, timeout_s=None)` — structured existence/readability, stream and duration checks

Defined in `project_agent_server.py` (`local-project-agent`):

Project and scenes:

- `create_project(project_id, title, description="", language="en", status="active", settings=None)` — creates a project scaffold; never overwrites an existing project
- `list_projects()` — lists project IDs, titles and statuses, reporting corrupt manifests per item
- `get_project(project_id)` — loads one full `project.json` manifest
- `add_scene(project_id, title, duration=5.0, scene_id=None, description="", narration="", image_prompt="", animation_prompt="", negative_prompt="", character_references=None, status="draft")` — appends and renumbers a scene
- `list_scenes(project_id)` — lists full scene records in manifest order
- `update_scene(project_id, scene_id, title=None, description=None, duration=None, narration=None, image_prompt=None, animation_prompt=None, negative_prompt=None, status=None, character_ids=None, character_references=None)` — applies only supplied fields

Images and animation:

- `generate_scene_image(project_id, scene_id, workflow=None, positive_prompt=None, negative_prompt=None, width=None, height=None, seed=None, steps=None, cfg=None, regenerate=False, compose_prompt=False, prompt_language=None, character_references=None, visual_style=None, color_palette=None, character_appearance=None, timeout_s=None, poll_interval_s=None)` — submits a job and returns a `submission_id` immediately
- `get_scene_image_job(submission_id=None, job_id=None)` — polls by submission or service job ID
- `retry_scene_image(project_id, scene_id, timeout_s=None, poll_interval_s=None)` — retries the latest failed/timed-out image job; creates a new job ID
- `generate_scene_video(project_id, scene_id, workflow=None, animation_prompt=None, negative_prompt=None, width=None, height=None, frames=None, fps=None, seed=None, regenerate=False, allow_default_prompt=False, timeout_s=None, poll_interval_s=None)` — submits an animation job without blocking
- `get_scene_video_job(submission_id=None, job_id=None)` — polls by submission or service job ID
- `retry_scene_video(project_id, scene_id, timeout_s=None, poll_interval_s=None)` — retries the latest failed/timed-out/cancelled video job; reuses the job ID and increments `attempt`
- `cancel_scene_video(job_id=None, submission_id=None)` — uses service cancellation for a known job, or cancels the tracked task before a job exists

Generation is serialised inside `local-project-agent` by an in-process `asyncio.Lock`. It does not coordinate GPU work from other MCP processes, including TTS or the legacy video server. See [ADR 0010](docs/adr/0010-project-mcp-server.md).

## Scene services (Python APIs)

The scene, image and animation services are MCP-independent Python APIs exposed through `local-project-agent`; there is no UI yet. Character registry and visual identity remain Python APIs only.

- `scene_image_service.py` generates a scene image sequentially from its approved prompt, verifies the PNG, and writes a versioned path to the scene manifest only after success.
- `scene_video_service.py` animates one approved scene image at a time with the verified LTX workflow. It validates the project, scene, image and prompt; checks workflow/model compatibility; uploads, submits, polls and downloads the MP4; verifies it with ffprobe; and updates only the target scene after verification.
- `video_workflows.json` keeps ComfyUI node IDs and verified settings out of service code. `workflow_adapter.py` validates and patches workflow copies without modifying `ltx_image_to_video_api.json`.
- Animation defaults are 768x512, 97 frames at 24 FPS (about 4.04 s). Custom dimensions, frames, FPS and seed are validated but were not separately smoke-tested. Planned scene duration is never treated as the generated duration; actual duration is measured after download.
- Outputs are written as `projects/{project_id}/video/scenes/scene-NNN-title.mp4` with `-v2`, `-v3`, and so on for regenerations. Finished files are never overwritten.
- Job tracking includes ComfyUI prompt ID, status, timestamps, attempts, errors and output path, with retry, regeneration, timeout and queued-job cancellation support. A failed job leaves the previous successful path unchanged.
- A default animation prompt is not used unless explicitly supplied or permitted by the caller.

## TTS setup — installed, smoke tests passed

Chatterbox Multilingual TTS is installed in `.venv-tts`. Short English and Hindi CUDA inference both passed using the cached model. `tts_service.py` wraps the official API, and two MCP tools expose generation and metadata reading. English (`en`) is the production target; Hindi (`hi`) is experimental and its output quality still needs evaluation.

### Official sources

- Repository: https://github.com/resemble-ai/chatterbox
- PyPI: https://pypi.org/project/chatterbox-tts/
- Windows/RTX issue: https://github.com/resemble-ai/chatterbox/issues/64

### Compatibility notes

Chatterbox supports English (`en`) and Hindi (`hi`). There is no official Hinglish language code, so Hinglish quality must be evaluated through practical testing.

Voice conditioning is supported through `audio_prompt_path`. Only recordings we own or are explicitly authorized to use may be used as references.

Expressiveness is controlled through parameters such as:

- `exaggeration`
- `cfg_weight`
- `temperature`
- `repetition_penalty`
- `min_p`
- `top_p`

There is no direct speaking-speed parameter in the official API. Speed control will require indirect parameter tuning or post-processing.

### Dependency warning

A plain install is **not safe** for this project:

```powershell
pip install chatterbox-tts
```

Chatterbox `0.1.7` pins:

```text
torch==2.6.0
torchaudio==2.6.0
```

for Python versions below 3.14. Our Python is 3.11, so a normal install would downgrade the working CUDA 13.0 / Blackwell stack.

The controlled installation is complete: `chatterbox-tts==0.1.7` was installed with `--no-deps`, followed by explicit compatible dependencies. `torch==2.10.0+cu130`, `torchaudio==2.10.0+cu130`, and `numpy==1.26.4` were preserved or restored. Gradio was not installed. See `docs/adr/0002-chatterbox-dependency-strategy.md` and `docs/adr/0003-windows-tts-dependency-pins.md`.

`pip check` reports expected Chatterbox metadata conflicts only: missing Gradio and a preference for Torch/TorchAudio `2.6.0`. These conflicts are intentional. Do not resolve them by downgrading Torch, TorchAudio, or CUDA, and do not install Gradio just to satisfy metadata.

WAV output uses `soundfile.write(...)` rather than `torchaudio.save(...)`, because the current environment does not include TorchCodec. Package imports, language codes, CUDA kernel execution, and short English/Hindi model inference have all passed. The smoke-test WAVs were 24 kHz, non-silent, and 3.52 s / 4.52 s respectively.

Before any GPU TTS stage, check ComfyUI VRAM: an empty render queue does not mean VRAM is free. If `GET /system_stats` shows low free VRAM, call `POST /free` with `{"unload_models":true,"free_memory":true}` and verify availability before starting TTS. ComfyUI reloads its models on the next render.

## FFmpeg media service (Phase 1)

FFmpeg and ffprobe 9.0.1 (essentials build) are installed at `C:\ffmpeg\ffmpeg-9.0.1-essentials_build\bin` and available on PATH; this was verified from PowerShell before implementation. Nothing was installed or upgraded for this milestone.

`media_service.py` is a standard-library-only service that owns every FFmpeg/ffprobe subprocess call. `media_server.py` wraps it as the third MCP server. No packages were added to `.venv`, and Torch/Chatterbox remain confined to `.venv-tts`.

### Implemented operations

| Operation | Behavior |
|---|---|
| `probe_media` | ffprobe duration, resolution, FPS, video/audio codecs, sample rate, channels and file size; structured `status="error"` for missing or invalid media |
| `merge_narration` | AAC audio at 192 kb/s, configurable volume, explicit duration handling, temp-file render, ffprobe validation before promotion |
| `validate_media` | existence, readability, video/audio streams, resolution, frame rate, audio metadata and optional expected duration with tolerance |

### Duration policies

- `trim_audio` — audio is matched to the video length. Longer narration is trimmed to the video; shorter narration is padded with silence. Video is stream-copied, preserving quality.
- `extend_video` — when narration is longer, the last video frame is frozen with `tpad` until narration ends. This requires libx264 re-encoding (`crf=18`, `preset=medium`). When narration is shorter, neither stream is cut and the remaining gap is reported.

Trims, silence padding, frame freezes and remaining gaps are always returned in `warnings` and timing fields such as `audio_trimmed_s` and `video_extended_s`; narration is never silently truncated.

### Safety and configuration

- Renders go to a hidden `.tmp.mp4` file in the destination folder and are promoted only after validation succeeds.
- Existing outputs are refused unless the caller passes `overwrite=True`. A second existence check prevents overwriting a file created during rendering.
- Subprocess timeouts are always set. Override with `MEDIA_FFMPEG_TIMEOUT_S` (default 180 s), `MEDIA_FFPROBE_TIMEOUT_S` (default 30 s), `MEDIA_FFMPEG_BIN` and `MEDIA_FFPROBE_BIN`.
- Expected media failures return structured results instead of crashing the MCP server.

### Known limitations

- Validation confirms readable streams and metadata, not perceptual A/V sync or narration content.
- Large renders occupy a worker thread; queueing and concurrency are not implemented.
- Only WAV narration input and MP4 output are supported in Phase 1.
- Music, sound effects, subtitles, transitions and multi-scene rendering are deliberately out of scope.
